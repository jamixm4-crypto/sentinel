# Карантин, откат и безопасное удаление

Архитектурный принцип Sentinel: **Сначала обратимая изоляция (карантин), и только потом — необратимое удаление.**

Шпионские программы часто используют сторожевые службы (watchdogs), взаимный мониторинг процессов (mutual respawn) и системные службы автозапуска. Попытка просто завершить процесс или удалить `.exe` файл в проводнике обычно приводит к моментальному перезапуску софта или блокировке удаления. Sentinel реализует строгую процедуру нейтрализации.

---

## Проблема сторожевых процессов (Watchdogs)

Классическая схема работы коммерческих кейлоггеров и stalkerware:

```
[Системная служба / Task Scheduler]
          │ (перезапуск при сбое)
          ▼
   [Watchdog.exe] ◄──────────────► [Payload.exe (Кейлоггер)]
   (Следит за процессом A)         (Следит за процессом B)
```

Если завершить `Payload.exe`, сторож `Watchdog.exe` моментально порождает его копию за доли секунды. Если завершить `Watchdog.exe`, служба Windows перезапустит его.

### Алгоритм нейтрализации в Sentinel

Когда пользователь запускает команду карантина или удаления (`sentinel quarantine <id>` или `sentinel remove <id>`), движок `Sentinel-Removal` выполняет операции в строго выверенном порядке:

1. **Деактивация автозапуска**:
   - Отключение записей реестра `Run` / `RunOnce` (переименование ключа во временное значение).
   - Отключение служб Windows (`sc config <name> start= disabled`).
   - Отключение задач Windows Task Scheduler (`schtasks /change /tn <task> /disable`).
   - В Linux: `systemctl disable --now <unit>`.
   - В macOS: выгрузка `launchctl bootout` / `unload`.
2. **Нейтрализация сторожей (Kill Watchdogs)**:
   - Принудительное завершение сторожевых служб и вспомогательных процессов-мониторов до того, как они успеют отреагировать.
3. **Завершение целевых процессов (Kill Payloads)**:
   - Завершение основных процессов записи и передачи данных.
4. **Перемещение в карантин**:
   - Исполняемые файлы и конфигурации не удаляются с диска, а атомарно перемещаются в защищённое изолированное хранилище.
   - Файлы получают расширение `.quarantine` и права доступа `chmod 000` (или запрещающие ACL под Windows).
5. **Создание манифеста изоляции**:
   - В каталоге карантина создаётся JSON-манифест с хешами файлов, исходными путями, правами доступа и резервными копиями реестра для обеспечения 100% обратимости.

## Структура хранилища карантина

По умолчанию карантин располагается в каталоге пользователя:
- **Windows**: `%LOCALAPPDATA%\sentinel\quarantine\` (или `C:\ProgramData\sentinel\quarantine\` при запуске с правами администратора).
- **Linux / macOS**: `~/.local/share/sentinel/quarantine/` (или `/var/lib/sentinel/quarantine/` при запуске от root).

Каждая операция создаёт отдельную директорию вида `<timestamp>-<rule_id>`:

```
~/.local/share/sentinel/quarantine/
└── 20261004-184512-mspy_windows/
    ├── manifest.json
    ├── payload.exe.quarantine
    ├── hookdll.dll.quarantine
    └── registry_backup.reg
```

### Формат файла `manifest.json`

```json
{
  "manifest_version": "1.0",
  "operation_id": "20261004-184512-mspy_windows",
  "rule_id": "mspy_windows",
  "rule_name": "mSpy Windows Agent",
  "timestamp": "2026-10-04T18:45:12Z",
  "quarantined_by": "user",
  "files": [
    {
      "original_path": "C:\\ProgramData\\mSpy\\agent.exe",
      "quarantined_name": "agent.exe.quarantine",
      "sha256": "4b227777d4dd1fc61c6f884f48641d02b4d121d3fd328cb08b5531fcacdabf8a",
      "size_bytes": 1048576,
      "permissions": "0755"
    }
  ],
  "autorun_entries": [
    {
      "type": "registry",
      "key": "HKCU\\Software\\Microsoft\\Windows\\CurrentVersion\\Run",
      "value_name": "mSpyAgent",
      "original_value": "C:\\ProgramData\\mSpy\\agent.exe"
    }
  ],
  "services": [
    {
      "name": "mSpyService",
      "original_start_type": "auto"
    }
  ]
}
```

## Восстановление из карантина (`restore`)

Если программа была изолирована по ошибке (например, администратор хочет вернуть программу удалённого доступа):

```bash
# Восстановление программы по ID правила
sentinel restore mspy_windows

# Автоматическое подтверждение
sentinel restore mspy_windows --yes
```

Движок восстановления:
1. Считывает `manifest.json` и проверяет контрольные суммы SHA-256 изолированных файлов.
2. Проверяет, свободен ли исходный целевой путь (не занят ли файл новым процессом).
3. Перемещает файлы обратно в исходное расположение.
4. Восстанавливает атрибуты файлов и права доступа.
5. Восстанавливает исходные записи автозапуска и типы запуска служб.
6. Удаляет запись из журнала карантина.

## Полное удаление (`remove`)

Необратимое удаление файлов применяется, когда пользователь уверен в необходимости полной очистки:

```bash
# Удаление конкретной подтверждённой угрозы
sentinel remove actual_spy

# Пакетное удаление всех однозначных угроз (категория safe_auto)
sentinel remove --all-safe
```

### Защитные барьеры при удалении:
1. **Категория `do_not_remove` (EDR / MDM)**: Команда завершится отказом с объяснением, что управление данным софтом закреплено за организацией.
2. **Категория `manual_review`**: Попытка вызвать `remove --all-safe` пропустит такие объекты. Для них требуется явное указание `sentinel remove <id>`.
3. **Интерактивное предупреждение**: Без ключа `--yes` утилита покажет точный список путей, которые будут удалены навсегда, и потребует явного ввода слова `yes`.
