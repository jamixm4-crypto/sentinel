# Справочник командной строки (CLI Reference)

Утилита **Sentinel** скомпилирована в виде единого автономного бинарного файла без внешних зависимостей.

```text
sentinel <КОМАНДА> [ПАРАМЕТРЫ]
```

---

## 1. Команда `scan`

Основная команда для анализа состояния операционной системы. Выполняется в режиме **read-only** (только чтение). По завершении формирует интерактивный терминальный отчёт, структурированный JSON и красивый автономный HTML-отчёт для браузера.

```bash
sentinel scan [OPTIONS]
```

### Параметры:

| Параметр | По умолчанию | Описание |
| :--- | :---: | :--- |
| `-l, --lang <en\|ru>` | `en` | Язык вывода и локализации описаний находок. Поддерживаются русский (`ru`) и английский (`en`). |
| `-o, --out <DIR>` | `.` | Путь к каталогу для сохранения сгенерированных отчётов (HTML, JSON). |
| `-q, --quiet` | `false` | **Тихий режим**: отключает баннеры и спиннеры; выводит только чистый вердикт или таблицу угроз. |
| `-v, --verbose` | `false` | **Подробный режим**: выводит метрики коллекторов, время сбора артефактов и пропущенные привилегии. |
| `--format <FMT>` | `terminal` | Формат вывода: `terminal`, `html`, `json`, `ndjson`, `ecs` (Elastic Common Schema v8.11). |
| `--scan-path <DIR>` | - | **Форензик-режим**: офлайн-сканирование внешней папки или смонтированного образа диска. |
| `--rules-dir <DIR>` | - | Путь к папке с пользовательскими YAML-правилами для сканирования. |
| `--allowlist <FILE>`| - | Путь к пользовательскому белому списку в формате JSON. |
| `--stdout-only` | `false` | Вывод только в терминал (in-memory); файлы отчётов не создаются на локальном диске. |
| `--no-open` | `false` | Не открывать сгенерированный HTML-отчёт в браузере по умолчанию автоматически. |
| `--personal-safety-mode` | `false` | **Режим защиты жертв сталкинга**: блокирует деструктивные действия и предотвращает создание файлов отчёта на диске. |
| `--online-lookups` | `false` | Опциональная проверка хешей файлов через внешние репутационные сервисы. |

### Примеры:

```bash
# Экспресс-сканирование с выводом на русском языке и автоматическим открытием HTML-отчета:
sentinel scan --lang ru

# Тихий режим для автоматизации (минималистичный вывод):
sentinel scan -q

# Подробный аудит с замером времени коллекторов:
sentinel scan -v

# Экспорт в Elastic Common Schema (ECS) для передачи в SIEM:
sentinel scan --format ecs

# Офлайн-инспекция смонтированного дискового образа:
sentinel scan --scan-path /mnt/suspect_image

# Режим личной безопасности (без следов на диске и без открытия браузера):
sentinel scan --lang ru --personal-safety-mode
```

## 2. Команда `quarantine`

Безопасная, обратимая изоляция обнаруженного ПО. Осуществляет нейтрализацию сторожевых процессов (watchdogs), деактивацию записей автозапуска и перемещение исполняемых файлов в защищённое изолированное хранилище с созданием криптографического манифеста отката.

```bash
sentinel quarantine <ID>
```

### Аргументы:
- `<ID>` — Идентификатор найденного объекта (например, `STK-WIN-0042-1` или ID правила `actual_spy`).

### Пример:
```bash
sentinel quarantine STK-WIN-0042-1
```

## 3. Команда `restore`

Полный откат ранее выполненной операции карантина: верификация целостности файлов по контрольным суммам SHA-256, восстановление файлов в исходные каталоги, возврат прав доступа и параметров автозапуска.

```bash
sentinel restore <ID>
```

### Аргументы:
- `<ID>` — Идентификатор карантинной записи или исходного правила.

### Пример:
```bash
sentinel restore STK-WIN-0042-1
```

## 4. Команда `remove`

Окончательное удаление файлов и параметров автозапуска с диска.

```bash
sentinel remove [ID] [OPTIONS]
```

### Параметры:
- `[ID]` — Идентификатор конкретной угрозы для удаления (доступно для категорий `SafeAuto` и `ManualReview`).
- `--all-safe` — Пакетное удаление всех подтверждённых находок со статусом `SafeAuto`. Программы категорий `ManualReview` и `DoNotRemove` пропускаются.
- `-y, --yes` — Подтверждение операции без интерактивного запроса «yes».
- `--personal-safety-mode` — Режим личной безопасности (блокирует операцию удаления во избежание настораживания преследователя).

### Примеры:
```bash
# Интерактивное удаление конкретной подтверждённой угрозы (потребует ввода слова "yes"):
sentinel remove STK-WIN-0042-1

# Пакетное автоматическое удаление всех однозначно шпионских программ:
sentinel remove --all-safe --yes
```

## 5. Команда `explain`

Вывод полной информации о сигнатуре, индикаторах компрометации, назначении ПО и пошаговых ручных рекомендаций по его обезвреживанию.

```bash
sentinel explain <ID> [OPTIONS]
```

### Параметры:
- `<ID>` — Идентификатор правила или обнаружения (например, `mspy_windows`, `STK-WIN-0042`).
- `-l, --lang <en|ru>` — Язык вывода (`en` или `ru`).

### Пример:
```bash
sentinel explain STK-WIN-0042 --lang ru
```

---

## 6. Команда `rules`

Управление базой правил, инспекция встроенных сигнатур и валидация новых правил.

```bash
sentinel rules <SUBCOMMAND>
```

### Подкоманды:

1. **`list`**: Вывод статистики и полного реестра загруженных правил (все 75+ встроенных сигнатур).
   ```bash
   sentinel rules list
   ```

2. **`validate <PATH>`**: Проверка синтаксиса и логической корректности YAML-файла правила против схемы.
   ```bash
   sentinel rules validate ./rules/stalkerware/new_rule.yml
   ```

3. **`update [--from <PATH>]`**: Офлайн-импорт внешних пакетов правил (.yml/.yaml) или списков C2-доменов (.txt):
   ```bash
   sentinel rules update --from ./offline_rules/
   sentinel rules update --from ./c2_domains.txt
   ```

---

## 7. Команда `allow`

Управление локальным пользовательским списком исключений (белым списком). Исключения позволяют подавлять ложные срабатывания на легитимное административное или мониторинговое ПО.

```bash
sentinel allow <SUBCOMMAND>
```

### Подкоманды:

1. **`list`**: Просмотр всех добавленных исключений.
   ```bash
   sentinel allow list
   ```

2. **`add <ENTRY>`**: Добавление ID правила, имени процесса или C2-домена в белый список.
   ```bash
   sentinel allow add "my_admin_tool.exe"
   sentinel allow add "STK-WIN-0042"
   ```

3. **`remove <ENTRY>`**: Удаление записи из белого списка.
   ```bash
   sentinel allow remove "my_admin_tool.exe"
   ```

## Коды возврата (Exit Codes)

| Код | Значение |
| :---: | :--- |
| `0` | Операция завершена успешно. При сканировании: угроз уровня `Critical` или `High` не обнаружено. |
| `1` | При сканировании обнаружены угрозы уровня `Critical` или `High`. |
| `2` | Ошибка параметров командной строки или парсинга аргументов. |
| `3` | Ошибка доступа (требуется запуск с повышенными привилегиями / правами администратора). |
| `4` | Ошибка выполнения операций карантина, восстановления или удаления. |
