Кроссплатформенный защитный сканер с открытым исходным кодом для выявления программ скрытого наблюдения: кейлоггеров, коммерческого сталкерского ПО (Stalkerware), скрытых утилит удалённого доступа (RAT), программ учёта рабочего времени, корпоративных EDR/MDM-агентов и сторожевых процессов (process watchers/anti-kill).

По умолчанию работает **строго на чтение** (read-only), без фоновых служб, без отправки телеметрии в сеть и с нулевым локальным следом в режиме повышенной безопасности.

## Быстрый старт

### 1. Рекомендуемый способ: Проверенные бинарные релизы

Для инструментов безопасности прямая передача скрипта в командный интерпретатор (`curl | bash` или `irm | iex`) несёт риски. Рекомендуется скачивать проверенные бинарные файлы с контрольной суммой:

1. Скачайте архив для вашей ОС со страницы [GitHub Releases](https://github.com/jamixm4-crypto/sentinel/releases/latest).
2. Сверьте контрольную сумму SHA-256 с файлом `SHA256SUMS`:
   ```powershell
   # Windows (PowerShell)
   $hash = (Get-FileHash -Path sentinel-windows-x86_64.zip -Algorithm SHA256).Hash.ToLower()
   $expected = (Get-Content SHA256SUMS | Select-String "sentinel-windows-x86_64.zip").Line.Split(" ")[0].ToLower()
   if ($hash -eq $expected) { Write-Host "✔ Контрольная сумма совпадает!" -ForegroundColor Green }
   ```
   ```bash
   # Linux / macOS
   sha256sum -c SHA256SUMS
   ```
3. Распакуйте и запустите `sentinel scan`.

### 2. Автоматическая установка (для быстрого развёртывания)

**Windows (PowerShell):**
```powershell
irm https://raw.githubusercontent.com/jamixm4-crypto/sentinel/main/install.ps1 | iex
```

**Linux и macOS (Bash):**
```bash
curl -fsSL https://raw.githubusercontent.com/jamixm4-crypto/sentinel/main/install.sh | bash
```

## Примеры запуска аудита

```bash
# 1. Стандартный аудит (спиннер прогресса + отчёт в консоль + автономный HTML-отчёт):
sentinel scan --lang ru

# 2. Тихий режим (минимальный вывод, без баннеров и спиннеров):
sentinel scan -q

# 3. Подробный режим (вывод метрик сбора, времени выполнения и пропущенных проверок):
sentinel scan -v

# 4. Режим личной безопасности (вывод строго в память консоли; 0 файлов на диске):
sentinel scan --personal-safety-mode

# 5. Форензик-режим (сканирование смонтированного образа диска или внешней папки):
sentinel scan --scan-path /mnt/extracted_disk

# 6. Экспорт для SIEM (Elastic Common Schema ECS или NDJSON):
sentinel scan --format ecs
sentinel scan --format ndjson

# 7. Подробный разбор инцидента, тактики MITRE ATT&CK и инструкции по реагированию:
sentinel explain STK-WIN-0042
sentinel explain stalkerware_c2_network_beacon

# 8. Офлайн-обновление базы правил и C2-доменов:
sentinel rules update --from /path/to/custom_rules/
sentinel rules update --from /path/to/c2_domains.txt
```

## Режим личной безопасности (`--personal-safety-mode`)

В ситуациях преследования и домашнего насилия внезапное отключение шпионской программы или сохранение отчёта на рабочий стол может насторожить преследователя и спровоцировать физическую агрессию:

- **Нулевой файловый след**: HTML и JSON файлы **не сохраняются** на локальный диск; результаты выводятся только в защищённое окно терминала.
- **Подавление автооткрытия браузера**: браузер не запускается автоматически, не оставляя истории просмотров и кэша.
- **Блокировка изменения системы**: все команды `remove` и `quarantine` **строго заблокированы** во избежание демаскировки жертвы.
- **Безопасные ресурсы**: ссылки на защитные организации и справочники помощи:
  - [Coalition Against Stalkerware](https://stopstalkerware.org)
  - Международный справочник служб поддержки: [Lila.help](https://lila.help)

## Безопасное удаление и карантин (Dry-Run по умолчанию)

Все операции удаления и карантина работают в режиме **сухого прогона (dry-run) по умолчанию**:
```bash
# 1. Симуляция карантина (показывает планируемые действия без модификации файлов):
sentinel quarantine STK-WIN-0042-1

# 2. Реальное перемещение в изолированное шифрованное хранилище:
sentinel quarantine STK-WIN-0042-1 --execute

# 3. Полный откат изменений и восстановление файлов:
sentinel restore <quarantine-id>

# 4. Симуляция удаления всех находок категории SafeAuto:
sentinel remove --all-safe

# 5. Реальное удаление:
sentinel remove --all-safe --execute
```

## Пользовательский белый список (Allowlist)

Если в вашей системе используется специфическая легитимная утилита, её можно внести в локальный список исключений:
```bash
sentinel allow list
sentinel allow add "my_custom_tool.exe"
sentinel allow remove "my_custom_tool.exe"
```

## Полное удаление и очистка отчётов

Sentinel оставляет минимальный след в системе и предоставляет средства для моментального и чистого удаления самого сканера, его хранилищ и созданных отчётов:

### 1. Встроенная команда `purge`
```bash
# Удалить только сформированные отчёты (sentinel-report-*.html/json/ndjson):
sentinel purge --reports-only -y

# Полная зачистка: удалить все отчёты, сбросить хранилище ~/.sentinel и деинсталлировать Sentinel:
sentinel purge -y
```

### 2. Скрипты удаления в одну команду
**Windows (PowerShell):**
```powershell
irm https://raw.githubusercontent.com/jamixm4-crypto/sentinel/main/uninstall.ps1 | iex
```

**Linux & macOS (Bash):**
```bash
curl -fsSL https://raw.githubusercontent.com/jamixm4-crypto/sentinel/main/uninstall.sh | bash
```

## Честные технические ограничения

1. **Мобильные телефоны (Android / iOS)**:
   Основная масса сталкерского ПО нацелена на смартфоны. Sentinel — сканер для рабочих станций (Windows, Linux, macOS). Он не может проверить внутреннюю память телефона без физического подключения через ADB или выгрузки резервной копии. Для мобильных устройств используйте **MVT (Mobile Verification Toolkit)** от Amnesty International или **TinyCheck**. Sentinel содержит базу C2-доменов мобильного ПО для детекции трафика в локальной сети.
2. **Руткиты уровня ядра (Ring 0)**:
   При компрометации ядра ОС проверки из пользовательского пространства не могут гарантировать 100% достоверность. При подозрении на руткиты рекомендуется проводить аудит со стороннего доверенного носителя.
3. **Аппаратные кейлоггеры**:
   Физические USB-перехватчики и аппаратные жучки в клавиатурах не определяются программными методами; требуется физический осмотр кабелей и разъёмов.

## Качество кода и CI-проверки безопасности

Все Pull Request и релизные теги проходят строгие автоматические проверки в GitHub Actions (Windows, Linux, macOS):

- **Стандарты форматирования**: `cargo fmt --check` гарантирует единообразие стиля кода.
- **Строгий линтинг**: `cargo clippy --all-targets --all-features -- -D warnings` запрещает любые предупреждения компилятора.
- **Аудит цепочки поставок**: `cargo audit` сверяет зависимости с базой RustSec Advisory Database (отсутствие известных CVE).
- **Лицензионная чистота**: `cargo deny check` контролирует лицензии и запрещает конфликтующие зависимости.
- **100% офлайн-тестирование**: интеграционные тесты проверяют корректность логики без единого исходящего сетевого запроса.
